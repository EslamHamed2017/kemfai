## Dependency and execution rules

1. IDs are exactly T159–T211, sequentially numbered.
2. T159–T176 are test/meta-evidence only and precede runtime implementation.
3. T177 is the first runtime implementation and directly depends on every task T159–T176.
4. Green claims cannot use mocks, interception, screenshots, responses alone, skips, retries, flaky/partial/transformed evidence, or survivor tolerance.
5. The exact required check is `accounting-foundation-owned-live`; exact-head means the candidate commit SHA, not a branch or earlier SHA.
6. Before T177 begins, T176 must persist read-only proof that this check exists, is required by main branch protection, and is green on the exact commissioning baseline (or a formally re-commissioned baseline). Any absence, non-green result, protection drift, or head drift blocks runtime implementation.
7. T177–T207 may be developed only on an isolated feature branch. No Story 4 runtime implementation may merge into main, develop, or another shared/integration branch until T208–T211 have completed in order for the exact candidate head.
